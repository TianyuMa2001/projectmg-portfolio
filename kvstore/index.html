01

The problem and my implementation

A replicated store must decide when a write is acknowledged, which version a read returns, and what a timeout actually means. I implemented and refined a single-leader, in-memory store with configurable write quorum W and read quorum R.

My work covers atomic per-key version allocation, parallel replication and peer reads, monotonic follower updates, explicit timeout responses, configuration validation, and reproducible correctness and fault checks.

02

A timeout is an uncertain outcome

The leader installs its local value before replication reaches quorum. If the deadline expires, responding as though nothing happened would mislead a client: a local write exists, and submitted replication may still finish.

The API returns HTTP 503 with status=indeterminate and localApplied=true. Successful writes return 201 after W acknowledgements, including the leader. A bounded executor submits replication to all followers even when W=1.

Followers reject conflicting same-version values and prevent older versions from overwriting newer ones. Quorum reads count reachable missing-key responses and select the highest version among collected responses.

03

Verification and an important correction

The recorded Java suite passed 10 tests covering concurrency, replication ordering, slow or unreachable peers, partial writes, reads, invalid inputs and application startup. The benchmark harness additionally checks the build hash, server PID, effective quorum settings and actual port unreachability.

An earlier benchmark terminated a Java launcher without proving the replica server was down. I withdrew that evidence and the associated 46.2% throughput uplift claim. This page makes no performance improvement claim from those results.

The corrected local quorum regression verified a five-node W=5 configuration with one replica stopped: all 186 measured writes across three runs returned 503, with no 201 responses. This is a focused failure-semantics check, not a complete throughput benchmark. Since no writes were acknowledged, stale-read rate is not calculable for that case.

04

Run it and understand the boundary

Build the JAR with the included Maven wrapper, then start the five-node cluster using Docker Compose. The repository README includes configuration, port mappings, and example read/write requests.

This is an educational single-leader prototype. Storage is volatile; there is no automatic leader election, durable log, persistent retry queue or consensus protocol. Quorum overlap alone does not establish production-grade linearizability under arbitrary partitions.
